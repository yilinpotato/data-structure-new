# 新能源物流车队协同调度系统

基于高德地图的新能源物流车队协同调度系统，实现了多种调度策略、多车协同配送、充电管理和实时可视化追踪功能。

## 项目概述

本项目模拟了一个中央仓库管理的新能源物流车队，在广州市真实地图上进行配送任务的调度与追踪。系统考虑了车辆电量限制、载重限制、充电站分布等因素，使用高德地图JS API实现真实道路路径规划和车辆行驶轨迹动画，提供类似高德导航/美团物流追踪的视觉效果。

### 主要功能

- **高德地图可视化**：基于高德地图JS API 2.0的真实地图展示，支持缩放、平移
- **真实道路路径规划**：使用AMap.Driving API计算沿真实道路的驾驶路线
- **车辆行驶轨迹动画**：车辆沿真实道路平滑移动，动态绘制行驶轨迹，带方向箭头
- **多种调度策略**：最近任务优先、最大任务优先、紧急任务优先
- **多车协同配送**：支持多辆车辆协同完成大型任务
- **充电管理**：车辆电量不足时自动规划充电站充电，模拟排队与负荷
- **WGS-84→GCJ-02坐标转换**：确保地点坐标与高德地图精确对齐
- **可拖拽面板**：车辆状态面板和任务列表面板支持拖拽移动
- **实时统计**：已完成/失败/待处理任务数、总评分实时更新
- **一键策略对比**：可直接跑完整个模拟时间，对比最近/最大/紧急/平衡策略和Gurobi静态最优

## 快速开始

### 1. 启动Web可视化平台

```bash
python app.py
```

启动后访问 http://127.0.0.1:5000

### 2. 配置高德地图API

系统使用高德地图JS API 2.0，需要配置以下参数：

1. 登录 [高德开发者平台](https://lbs.amap.com/) 注册账号
2. 创建应用，选择「Web端(JS API)」类型，获取Key和安全密钥
3. 在 `templates/index.html` 中配置：
   - **API Key**：搜索 `key=` 替换为你的Key
   - **安全密钥**：搜索 `securityJsCode` 替换为你的安全密钥

### 3. 使用Web界面

1. 打开浏览器访问 http://127.0.0.1:5000
2. 在左侧面板设置模拟参数：
   - **车队规模**：3-20辆车
   - **模拟时间**：60-7200秒
   - **任务生成率**：0.01-1（每秒生成任务的概率）
   - **调度策略**：最近任务优先/最大任务优先/紧急任务优先/平衡策略
3. 点击「▶ 开始模拟」按钮进行实时动画模拟，或点击「⚡ 一键跑完所有策略」直接完成全时长策略对比
4. 观察地图上的车辆调度动画：
   - 🚛 彩色卡车图标沿真实道路移动
   - 实线轨迹表示已走过的路径（带方向箭头）
   - 虚线表示规划路线
   - 灰色底线表示完整路线预览
   - 🟢 绿色圆点标记起点
   - 🔴 红色圆点标记终点
5. 拖拽「车辆状态」和「当前任务」面板到合适位置
6. 在「一键策略对比」表格中查看各策略完成率、总分、平均任务得分和充电次数

### 4. 命令行模式

```bash
# 基本运行
python main.py --visualize --show-map

# 启用协同配送和充电管理
python main.py --strategy nearest --enable-cooperation --enable-charging --visualize

# 比较不同策略
python main.py --compare-strategies --runs-per-strategy 5 --visualize
```

命令行参数：
- `--fleet-size`：车队规模（默认10）

- `--task-rate`：任务生成概率（默认0.01）
- `--strategy`：调度策略（nearest/max_weight/urgency/balanced）
- `--enable-cooperation`：启用多车协同
- `--enable-charging`：启用充电管理
- `--visualize`：生成可视化
- `--show-map`：显示地图
- `--compare-strategies`：比较策略

- **行驶速度**：0.5公里/步

## 调度策略

### 1. 最近任务优先（Nearest）

优先分配距离车辆当前位置最近的任务。适合配送区域集中、任务密集的场景。

### 2. 最大任务优先（Max Weight）

优先分配货物重量最大的任务。适合运力充足、需要优先处理大宗订单的场景。

### 3. 紧急任务优先（Urgency）

综合考虑任务截止时间和距离，优先分配即将超时的任务。适合对时效性要求高的场景。

### 4. 平衡策略（Balanced）

综合考虑距离、任务重量、截止时间和车辆电量余量，为每辆车选择当前收益/风险比较优的任务。该策略适合作为强化学习策略的强基线，也可作为训练早期的专家参考。

## 强化学习策略设计

本项目后续可以设计一个“得分导向的强化学习调度策略”，目标不是单纯学习最短路，而是学习在动态任务、电量约束、充电排队和车辆分布变化下，使总评分尽可能接近当前最强启发式策略，甚至在高负荷场景下超过固定规则策略。

### 设计目标

- 最大化总评分：完成任务越早、路径越短、超时越少，累计得分越高。
- 减少低电量风险：车辆在接任务前要保留到达充电站或仓库的安全电量。
- 减少充电排队损失：避免所有车辆集中到同一个充电站。
- 提高车辆利用率：在多种任务候选中学习更合适的派车顺序。
- 保持策略稳定：训练出的策略不能只在某一种规模下表现好，应能适应小/中/大规模场景。

### 环境建模

强化学习环境可以直接复用当前模拟器：

- 道路网络：节点表示真实地点，边表示道路连接，边权为距离或综合行驶成本。
- 智能体：可以先采用“中央调度器单智能体”方案，由一个策略统一决定所有空闲车辆的动作；后续再扩展为多智能体。
- 时间步：每个模拟步长触发一次任务生成、车辆移动、充电更新、任务分配和统计更新。
- 约束：车辆载重、电量、充电站容量、排队队列、任务截止时间。
- 场景规模：训练时混合使用小规模、中规模、大规模，避免策略过拟合单一任务密度。

### 状态设计

为了让策略既能看见局部车辆状态，也能理解全局供需分布，状态可包含以下特征：

| 类别 | 状态特征 |
|------|---------|
| 车辆特征 | 当前节点、电量百分比、载重上限、当前状态、是否空闲、到最近充电站距离 |
| 任务特征 | 任务节点、货物重量、等待时间、剩余截止时间、预估完成距离 |
| 充电站特征 | 充电站节点、可用充电桩数量、当前排队长度、历史平均负荷 |
| 局部供需特征 | 当前待处理任务数量、紧急任务数量、最近候选任务距离 |
| 全局统计 | 当前时间、总任务数、完成率、失败率、当前总分、车辆利用率 |

实际训练时可以只取每辆车附近 Top-K 个候选任务和 Top-K 个候选充电站，避免状态维度过大。

### 动作设计

当前实现不直接控制车辆每一步怎么开，而是控制“选择哪一种专家调度动作”：

| 动作类型 | 说明 |
|---------|------|
| `nearest` | 使用最近任务优先专家 |
| `max_weight` | 使用最大任务优先专家 |
| `urgency` | 使用紧急任务优先专家 |
| `balanced` | 使用平衡策略专家 |

动作空间使用安全筛选：超载任务、电量不足且无可达充电站的任务、不可达节点都直接屏蔽；如果 RL 给出的动作没有合法任务，则自动回退到平衡/紧急等安全策略。

### 奖励函数

奖励应尽量贴近最终评分，而不是只奖励完成任务：

| 奖励项 | 设计 |
|--------|------|
| 任务完成奖励 | 使用当前任务评分作为主要正奖励 |
| 时间奖励 | 比截止时间越早完成，额外奖励越高 |
| 距离惩罚 | 行驶距离越长，惩罚越高 |
| 超时惩罚 | 任务超时失败时给予较大负奖励 |
| 低电量风险惩罚 | 接任务后无法到达充电站或仓库时惩罚 |
| 排队惩罚 | 进入高负荷充电站或长队列时惩罚 |
| 选择质量奖励 | 完成任务和减少失败会通过总分变化反馈给对应调度选择 |

推荐总奖励：

```text
reward =
  任务评分
  - 路径距离成本
  - 超时失败惩罚
  - 低电量风险惩罚
  - 充电排队惩罚
  + 完成任务增量奖励
```

### 策略结构建议

当前代码采用“启发式专家 + 表格 Q-learning”的混合策略，避免额外引入深度学习依赖，也便于报告解释：

1. 将状态离散为电量档位、待处理任务数量、紧急任务数量、最近任务距离和充电站压力。
2. 动作不是直接选任务编号，而是在最近/最大/紧急/平衡四个专家中选择一个。
3. 每次模拟步根据总分变化、完成任务增量和失败任务增量更新 Q 表。
4. 训练时使用 epsilon-greedy 探索，epsilon 从较高值逐渐下降。
5. 部署时读取 `models/rl_q_table.json`，epsilon 设为 0，始终选择当前 Q 值最高的专家动作。

训练命令示例：

```bash
python train_rl.py --episodes 120 --eval-runs 8 --fleet-size 8 --simulation-time 1800 --task-rate 0.12 --node-count 16
```

训练完成后，Web 界面的策略下拉框可以选择“强化学习策略”，一键模拟表格也会把 `rl` 纳入对比。

### 训练与评估方案

- 训练场景：随机混合不同车队规模、节点数量、任务生成率、截止时间比例和充电站容量。
- 课程学习：先训练低任务密度场景，再逐步提高任务密度和充电站压力。
- 对比基线：最近任务优先、最大任务优先、紧急任务优先、平衡策略。
- 验证指标：总评分、完成率、失败率、平均任务得分、平均任务用时、总行驶距离、充电次数、平均充电排队长度。
- 选择最佳策略：不是选择训练奖励最高的一次，而是在固定验证集上多次运行，选择平均总评分最高且失败率稳定的模型。

### 预期效果

强化学习策略最可能提升的部分不是单个最短路径，而是全局调度时机：

- 在任务密集时，学习哪些任务应该先抢、哪些可以等待。
- 在电量不足前，提前选择负荷较低的充电站。
- 在不同规模场景中，自动调整“抢近单、拿大单、保电量、避排队”的权重。

因此强化学习策略的目标是接近或超过当前“平衡策略”的总评分，并在大规模、高任务率、充电站压力较高的场景中体现优势。

## Gurobi静态最优对比

除动态调度策略外，系统预留了 Gurobi 静态上帝视角求解器，用于给强化学习提供专家策略和性能上界。静态最优假设某一段模拟时间内的任务全部已知，然后建立混合整数规划模型，直接优化车辆访问任务的方案。

### 模型目标

Gurobi模型最大化静态总收益：

```text
最大化：任务完成收益 - 行驶距离惩罚 - 超时失败扣分
```

其中任务完成收益与模拟器评分对齐，包含基础得分、按时完成奖励和货物重量奖励；距离惩罚使用最短路径距离；只有在模拟时间内已经超时且未完成的任务才扣分。

### 决策变量

| 变量 | 含义 |
|------|------|
| `served[t]` | 任务 t 是否被完成 |
| `visit[v,t]` | 车辆 v 是否服务任务 t |
| `x[v,i,j]` | 车辆 v 是否从节点/任务 i 行驶到节点/任务 j |
| `arrival[v,t]` | 车辆 v 到达任务 t 的时间 |
| `order[v,t]` | MTZ顺序变量，用于消除子回路 |

### 约束条件

- 每个任务最多由一辆车服务。
- 车辆只能服务不超过自身载重上限的任务。
- 每辆车从中央仓库出发，形成连续开放路径，不强制瞬移回仓。
- 车辆路径满足流守恒约束。
- 使用MTZ约束避免子回路。
- 到达时间必须晚于任务生成时间。
- 有截止时间的任务必须在截止时间前到达。
- 单辆车总行驶时间不能超过模拟总时长。

### 与强化学习的关系

Gurobi静态最优不用于实时动画调度，而是作为“上帝视角专家”：

1. 在同一批任务上求出高质量车辆-任务-顺序方案。
2. 把状态、动作、路线选择记录为专家样本。
3. 强化学习先模仿 Gurobi 和平衡策略，获得较强初始策略。
4. 再在动态任务流中用奖励函数微调，学习实时调度时的取舍。

如果本机未安装 `gurobipy` 或没有可用 license，Web界面的 Gurobi 行会显示不可用；其他动态策略仍可一键跑完。当前版本将 `MIPGap` 设为 0，只有当 Gurobi 返回 `OPTIMAL` 时才把该行标记为“Gurobi静态最优”，表示已经证明当前静态模型下的全局最大总分。若达到时间限制但还没有证明最优，界面会标注“Gurobi精确求解(未证明)”并显示 gap。

## 评分系统

- 任务完成时间越早、路径越短，获得的评分越高
- 约80%的任务带有时间限制，截止时间会随模拟总时长缩放，因此小规模演示也会出现紧急任务
- 超时未完成或车辆迟到到达的任务扣分
- 评分公式考虑了距离成本和时间成本

- **Flask**：Web服务器，提供REST API
- **NetworkX**：图结构建模和Dijkstra最短路径
- **多线程**：模拟线程与Web服务分离

### 路径规划流程

```
后端Dijkstra计算节点间最短路径
    → 前端AMap.Driving计算真实道路坐标
    → 路径插值生成平滑轨迹点
    → 动态绘制轨迹线 + 车辆移动动画
```

## API接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 主页面 |
| `/start_simulation` | POST | 启动模拟 |
| `/stop_simulation` | POST | 停止模拟 |
| `/get_state` | GET | 获取当前模拟状态 |
| `/get_graph_data` | GET | 获取地图图数据 |

```json
    "task_rate": 0.15,
    "strategy": "nearest"

```

## 常见问题

### 1. 地图加载不出来
- 检查网络连接，确保能访问 `webapi.amap.com`
- 确认API Key和安全密钥配置正确
- 按 `Ctrl+Shift+R` 强制刷新浏览器缓存

### 2. 路线不贴合道路（直线穿越建筑物）
- 确认安全密钥（securityJsCode）已正确配置
- 按F12查看控制台，确认 `Driving test OK` 出现
- 如果显示 `Driving test FAILED`，检查Key是否开通了路径规划服务

### 3. 车辆图标不显示
- 确认浏览器支持SVG渲染
- 检查控制台是否有JavaScript错误

### 4. 端口被占用
```bash
# Windows查看占用进程
netstat -ano | findstr :5000
# 终止进程
taskkill /PID <PID> /F
```
