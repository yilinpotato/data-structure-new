# 新能源物流车队协同调度系统

基于高德地图的新能源物流车队协同调度系统，实现了多种调度策略、多车协同配送、充电管理和实时可视化追踪功能。

## 项目概述

本项目模拟了一个中央仓库管理的新能源物流车队，在广州市真实地图上进行配送任务的调度与追踪。系统考虑了车辆电量限制、载重限制、充电站分布等因素，使用高德地图JS API实现真实道路路径规划和车辆行驶轨迹动画，提供类似高德导航/美团物流追踪的视觉效果。

### 主要功能

- **高德地图可视化**：基于高德地图JS API 2.0的真实地图展示，支持缩放、平移
- **真实道路路径规划**：使用AMap.Driving API计算沿真实道路的驾驶路线
- **车辆行驶轨迹动画**：车辆沿真实道路平滑移动，动态绘制行驶轨迹，带方向箭头
- **多种调度策略**：最近任务优先、最大任务优先、紧急任务优先
- **多车协同配送**：支持多辆车辆协同完成大型任务
- **充电管理**：车辆电量不足时自动规划充电站充电，模拟排队与负荷
- **WGS-84→GCJ-02坐标转换**：确保地点坐标与高德地图精确对齐
- **可拖拽面板**：车辆状态面板和任务列表面板支持拖拽移动
- **实时统计**：已完成/失败/待处理任务数、总评分实时更新

## 快速开始

### 1. 启动Web可视化平台

```bash
python app.py
```

启动后访问 http://127.0.0.1:5000

### 2. 配置高德地图API

系统使用高德地图JS API 2.0，需要配置以下参数：

1. 登录 [高德开发者平台](https://lbs.amap.com/) 注册账号
2. 创建应用，选择「Web端(JS API)」类型，获取Key和安全密钥
3. 在 `templates/index.html` 中配置：
   - **API Key**：搜索 `key=` 替换为你的Key
   - **安全密钥**：搜索 `securityJsCode` 替换为你的安全密钥

### 3. 使用Web界面

1. 打开浏览器访问 http://127.0.0.1:5000
2. 在左侧面板设置模拟参数：
   - **车队规模**：3-20辆车
   - **模拟时间**：60-7200秒
   - **任务生成率**：0.01-1（每秒生成任务的概率）
   - **调度策略**：最近任务优先/最大任务优先/紧急任务优先
3. 点击「▶ 开始模拟」按钮
4. 观察地图上的车辆调度动画：
   - 🚛 彩色卡车图标沿真实道路移动
   - 实线轨迹表示已走过的路径（带方向箭头）
   - 虚线表示规划路线
   - 灰色底线表示完整路线预览
   - 🟢 绿色圆点标记起点
   - 🔴 红色圆点标记终点
5. 拖拽「车辆状态」和「当前任务」面板到合适位置

### 4. 命令行模式

```bash
# 基本运行
python main.py --visualize --show-map

# 启用协同配送和充电管理
python main.py --strategy nearest --enable-cooperation --enable-charging --visualize

# 比较不同策略
python main.py --compare-strategies --runs-per-strategy 5 --visualize
```

命令行参数：
- `--fleet-size`：车队规模（默认10）
- `--simulation-time`：模拟时间/秒（默认28800，即8小时）
- `--task-rate`：任务生成概率（默认0.01）
- `--strategy`：调度策略（nearest/max_weight/urgency/balanced）
- `--enable-cooperation`：启用多车协同
- `--enable-charging`：启用充电管理
- `--visualize`：生成可视化
- `--show-map`：显示地图
- `--compare-strategies`：比较策略

## 车辆模型

系统包含三种类型的车辆：

| 类型 | 载重 | 电量上限 | 充电速率 |
|------|------|---------|---------|
| 大型车 | 1500kg | 100单位 | 25单位/步 |
| 中型车 | 800kg | 80单位 | 20单位/步 |
| 小型车 | 500kg | 60单位 | 15单位/步 |

- **电量消耗**：0.3单位/公里
- **行驶速度**：0.5公里/步
- 低电量（<30%）时优先前往充电站
- 充电站有容量限制，模拟排队等待

## 调度策略

### 1. 最近任务优先（Nearest）

优先分配距离车辆当前位置最近的任务。适合配送区域集中、任务密集的场景。

### 2. 最大任务优先（Max Weight）

优先分配货物重量最大的任务。适合运力充足、需要优先处理大宗订单的场景。

### 3. 紧急任务优先（Urgency）

综合考虑任务截止时间和距离，优先分配即将超时的任务。适合对时效性要求高的场景。

## 评分系统

- 任务完成时间越早、路径越短，获得的评分越高
- 超时未完成的任务扣分
- 评分公式考虑了距离成本和时间成本

## 技术架构

### 前端
- **高德地图JS API 2.0**：地图渲染、路径规划、坐标转换
- **AMap.Driving**：真实道路驾驶路线计算
- **AMap.Polyline**：轨迹线绘制（底线+虚线+实线三层渲染）
- **纯JavaScript**：无框架依赖，原生DOM操作
- **CSS3动画**：脉冲动画、拖拽交互

### 后端
- **Flask**：Web服务器，提供REST API
- **NetworkX**：图结构建模和Dijkstra最短路径
- **多线程**：模拟线程与Web服务分离

### 路径规划流程

```
后端Dijkstra计算节点间最短路径
    → 前端AMap.Driving计算真实道路坐标
    → 路径插值生成平滑轨迹点
    → 动态绘制轨迹线 + 车辆移动动画
```

## 常见问题

### 1. 地图加载不出来
- 检查网络连接，确保能访问 `webapi.amap.com`
- 确认API Key和安全密钥配置正确
- 按 `Ctrl+Shift+R` 强制刷新浏览器缓存

### 2. 路线不贴合道路（直线穿越建筑物）
- 确认安全密钥（securityJsCode）已正确配置
- 按F12查看控制台，确认 `Driving test OK` 出现
- 如果显示 `Driving test FAILED`，检查Key是否开通了路径规划服务

### 3. 车辆图标不显示
- 确认浏览器支持SVG渲染
- 检查控制台是否有JavaScript错误

### 4. 端口被占用
```bash
# Windows查看占用进程
netstat -ano | findstr :5000
# 终止进程
taskkill /PID <PID> /F
```
